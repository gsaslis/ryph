The first account registered becomes the only admin. A fresh control plane logs a setup token for
that registration:

  kubectl -n {{ include "ryph.ns.services" . }} logs deploy/control-plane -c control-plane | grep "Setup token"

IMPORTANT: the security boundary between agent runs and everything else is a set of
NetworkPolicies. They only mean something on a cluster whose network plugin ENFORCES them
(README.md, "Requirements"). On one that does not, every run can reach the database, the services'
control listeners and the cloud metadata server.
{{- if and (include "ryph.routesHooks" .) (not .Values.networkPolicy.frontDoor.from) }}

WARNING: the front door routes /v1/hooks/ to the forge and the automations service, but
networkPolicy.frontDoor.from is empty, so their NetworkPolicies admit nothing from outside the
cluster: GitHub and GitLab webhooks and automation hooks will time out. Set it to your load
balancer's ranges or your ingress controller's namespace.
{{- end }}

{{- if not .Values.runs.runtimeClassName }}

Note: runs.runtimeClassName is empty, so agent runs share the node's kernel. A sandboxing runtime
(gVisor) is strongly recommended wherever untrusted repositories or models run.
{{- end }}
{{- if and .Values.environments.enabled (eq (.Values.environments.builder | default "kubernetes") "kubernetes") (not (.Values.environments.runtimeClassName | default .Values.runs.runtimeClassName)) }}

WARNING: environments.allowUnsandboxed is on, so environment builds run in
{{ include "ryph.ns.builds" . }} with no runtimeClassName (environments.runtimeClassName, else
runs.runtimeClassName). BuildKit there executes repositories' Dockerfiles and setup.yml with seccomp
and AppArmor unconfined, on the node's own kernel: a kernel bug in a RUN step is the node. Laptop
clusters only; anywhere else, install gVisor and set the runtime class.
{{- end }}
{{- if not .Values.tools.runtimeClassName }}

Note: tools.runtimeClassName is empty, so hosted MCP servers (vendors' containers) share the
node's kernel. A sandboxing runtime (gVisor) is recommended for them too.
{{- end }}
{{- if and .Values.secrets.generate (not .Values.devState.enabled) }}

Internal credentials this chart generated are kept in the cluster and reused on upgrade. Back up
RYPH_SECRETS_KEY, RYPH_MCP_KEY and RYPH_CHAT_KEY: what they seal is lost with them. A render without
cluster access (helm template, Argo CD) cannot see them and refuses to mint new ones: see
README.md, "Secrets".
